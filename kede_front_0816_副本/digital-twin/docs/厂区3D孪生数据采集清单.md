# 养鱼厂区 3D 数字孪生 · 数据采集清单

把**整个厂区**做成与 Demo 同类的 3D 孪生效果时：三维扫描几乎是必做，但扫描只是空间底座。本清单按用途分类，便于采购、现场配合与后期对接。

> 技术路线参考：点云 → CloudCompare → Blender 白模 → glTF → Three.js（设备数据可模拟或对接真实系统）。不强制使用 Revit 等专业 BIM。

---

## 一、空间底座（建模用）

| 优先级 | 数据项 | 说明 | 交付建议 |
| --- | --- | --- | --- |
| 必做 | 三维激光扫描 / 摄影测量 | 厂房内外、鱼池、管廊、设备区；多站拼接成完整点云 | PLY / LAS / E57，分块归档 |
| 必做 | 厂区平面图 / 总图 | 建筑轮廓、道路、分区；用于对坐标、裁剪、核对 | CAD 或带比例 PDF |
| 强烈建议 | 坐标系与标高约定 | 原点位置、正北方向、层高 / ±0.000 | 一页说明即可 |
| 建议 | 分区扫描计划 | 按车间 / 鱼池区 / 水处理 / 仓库分块扫，控制单文件体积 | 测站位置标注在总图上 |
| 可选 | BIM / CAD 模型 | Revit、SketchUp 等，便于对照；轻量孪生非必须 | 有则附 RVT/SKP/IFC |
| 可选 | 航拍 / 倾斜摄影 | 室外厂区、屋顶、道路；室内仍靠地面激光 | 正射 / 倾斜成果 |

**空间底座检查**

- [ ] 已完成试点区域扫描（建议先 1 个车间）
- [ ] 原始点云已放入 `assets/pointcloud/raw/`（或等价归档）
- [ ] 总图与测站位置图齐全
- [ ] 坐标系 / 标高已书面约定

## 二、扫描现场准备

| 类别 | 事项 |
| --- | --- |
| 通行 | 可进入的房间、走道、盖板；减少遮挡 |
| 时段 | 尽量低干扰（水雾、蒸汽、强反光会降质） |
| 难点区 | 金属 / 玻璃 / 水面提前知情，预留补扫或手工补模 |
| 安全 | 涉水、电气、高空走道需陪同与许可 |
| 配合 | 现场联系人、配电/阀门是否可临时标识 |

**现场检查**

- [ ] 扫描路径与开放区域已确认
- [ ] 安全与陪同安排到位
- [ ] 反光 / 水面 / 蒸汽等难点已告知扫描方

## 三、语义与设备台账（可点选交互）

扫描只得到形状；「点哪里是什么」需单独建台账。

| 数据项 | 用途 | 示例字段 |
| --- | --- | --- |
| 设备台账 | 列表、详情、报警归属 | 名称、业务编码、类型、所属车间 |
| 位置对照 | 在点云 / 总图上放 `Hotspot_*` | 大致坐标或「某池北侧」描述 + 照片 |
| 工艺分区 | 分层显示、筛选 | 育苗 / 养成 / 循环水处理 / 配电 / 仓库 |
| 管线 / 流向简图 | 后期流向动画、工艺联动 | P&ID 或手绘即可；第一期可简化 |

**锚点命名建议（与前端一致）**

| 空物体名（glTF） | 含义 |
| --- | --- |
| `Hotspot_Tank_01` … | 鱼池 |
| `Hotspot_Pump_01` … | 水泵 |
| `Hotspot_Sensor_DO_01` … | 溶氧等传感器 |

原则：**3D 锚点名 ↔ 业务设备编码一一对应**（如 `Hotspot_Tank_A01` = `TANK-A01`）。

**台账检查**

- [ ] 试点车间设备清单已列出（池 / 泵 / 传感器 / 投喂机等）
- [ ] 每台设备有唯一业务 ID
- [ ] 已标注拟挂载热点的位置
- [ ] 分区名称中文已定稿

---

## 四、实时 / 业务数据（真孪生，非仅白模）

第一期可用前端模拟数据；上线真实孪生再备齐下列项。

| 数据类 | 示例 | 备注 |
| --- | --- | --- |
| 水质 | 水温、溶氧、pH、氨氮、浊度 | 按池或按探头 |
| 设备状态 | 泵开停、频率、投喂次数、液位 | 与设备 ID 对齐 |
| 报警 | 阈值、等级、时间、关联设备 | 绿 / 黄 / 红规则可先简化 |
| 对接方式 | MQTT / HTTP / SCADA / 现有业务库 | 约定刷新频率 |
| 统一设备 ID | 与 3D 锚点、台账同一套编码 | **关键，后期改成本最高** |

**数据对接检查**

- [ ] 已选定对接方式（接口文档或表结构）
- [ ] 设备 ID 与 3D 锚点映射表已建立
- [ ] 报警等级与阈值规则已书面确认
- [ ] 刷新频率已约定（如 1～5 秒 / 按需）

## 六、推荐落地顺序

1. **试点 1 个车间**：扫描 → 清洗 → 白模 → 挂 6～20 个热点 + 模拟/真实数据  
2. **固化命名与 ID 规范**（台账 + Hotspot + 接口三方一致）  
3. **扩展全厂**：按楼栋 / 车间分块扫描与分块 `*.glb`  
4. **接入真实遥测与报警**，替换模拟数据  

相关操作文档：

- [CloudCompare 处理 SOP](./cloudcompare-sop.md)
- [Blender 白模与 glTF 导出 SOP](./blender-sop.md)

## 七、一页总览（给领导 / 采购）

| 要整厂这种 3D | 需要 |
| --- | --- |
| 空间 | 三维扫描（或等价测绘）+ 总图 + 坐标标高 |
| 可点选 | 设备台账 + 位置对照 + 锚点命名 |
| 真孪生 | 统一设备 ID + 实时数据接口 + 报警规则 |
| 非必须 | Revit 等专业 BIM（有更好，没有也能走点云白模） |

**最小试点包（建议先采这些）**

1. 一个车间的点云（已去噪可拼接）  
2. 该车间平面图  
3. 设备台账 Excel（含唯一 ID）  
4. 6～20 个拟挂载设备的位置说明或现场照片  
5.（可选）1～2 路真实测点接口，用于演示真数据

## 八、台账 Excel 字段模板（可复制）

建议列：

| 字段 | 说明 |
| --- | --- |
| `device_id` | 业务唯一编码，如 `TANK-A01` |
| `name` | 中文名，如「一号养成池」 |
| `type` | `tank` / `pump` / `sensor` / 其他 |
| `zone` | 分区，如「养成一车间」 |
| `hotspot` | glTF 空物体名，如 `Hotspot_Tank_A01` |
| `building` | 楼栋 / 厂房 |
| `note_location` | 位置备注或总图坐标 |
| `photo` | 现场照片文件名（可选） |
| `data_source` | 模拟 / MQTT / HTTP / 库表名 |
| `enabled` | 是否在 3D 中显示 |
