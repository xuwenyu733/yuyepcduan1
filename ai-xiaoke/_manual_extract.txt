3.2 Agents 
“Agents”页面用于查看和管理企业内已创建的智能体。用户可以在此了解 Agent 的运行机制、
查看智能体信息，并进行接入、版本发布等操作。 
 
 
1. 查看 Agent 说明 
页面顶部展示 Agent 的基础说明，包括： 
• Agent 由模型、角色设定、技能和工具等配置组成。 
• Agent 分享给团队成员后，每位用户首次打开时，系统会自动创建独立的 Session。 
• 不同 Session 拥有独立的云端沙箱环境，对话记录和工作文件会保存在对应 Session 中。 
• “Session 数”表示当前基于该 Agent 创建的 Session 总数，包括通过分享链接或 API 创建的 
Session。 
2. 搜索 Agent 
在搜索框中输入 Agent 名称或 Agent ID，可以快速查找对应的智能体。 
3. 创建 Agent 
点击页面右上角的 创建 Agent，系统将跳转至“快速开始”页面。 
用户可以通过自然语言描述、空白 Agent 或预置模板创建新的企业智能体。 


===== PAGE 17 =====
4. 查看 Agent 列表 
列表中展示以下信息： 
• Agent 名称：智能体名称及简要介绍；未完成发布的 Agent 会显示“未发布”标识。 
• Agent ID：系统为 Agent 生成的唯一标识，可用于接入或定位 Agent。 
• 模型：当前 Agent 使用的模型。 
• 版本：当前已发布的版本号。 
• 状态：控制 Agent 是否启用。 
• 更新时间：Agent 最近一次更新的时间。 
• 创建人：创建该 Agent 的用户。 
• Session 数：当前基于该 Agent 创建的 Session 数量。 
• 操作：提供接入、版本发布及更多管理操作。 
 
5. 启用或停用 Agent 
通过“状态”列中的开关，可以启用或停用 Agent。 
停用后，Agent 将暂时不可继续提供服务；重新开启后即可恢复使用。正式使用中的 Agent 建
议谨慎调整状态。

点击操作列中的 接入，可以进入 Agent 的接入配置。 
该功能通常用于将 Agent 接入企业应用、业务系统或其他使用渠道。未发布的 Agent 暂不支持
接入。

3.3 Runtimes 
“Runtimes”页面用于查看和管理企业智能体对应的云端运行环境，主要帮助管理员了解各个 
Session 的沙箱运行状态，并在出现异常时定位问题。 
 
 
1. Runtime 是什么 
Runtime 是 Session 背后实际运行的云端沙箱环境，拥有独立的： 
• 文件系统 
• 进程环境 
• 网络环境 
每个 Session 创建时，系统会自动分配一个 Runtime。Agent 在会话中进行的代码执行、文件读
写和命令运行等操作，都会在对应的 Runtime 中完成。 
通常情况下，Session 与 Runtime 一一对应。 
2. 筛选 Runtime 
通过列表上方的状态筛选框，可以按照 Runtime 状态查看运行环境，例如查看全部、运行中或
异常状态的 Runtime。 


===== PAGE 20 =====
3. 查看 Runtime 列表 
列表中展示以下信息： 
• Runtime 名称：对应运行环境的名称，通常与关联的 Agent 或 Session 有关。 
• Runtime ID：系统为 Runtime 生成的唯一标识。 
• 沙箱模板：创建 Runtime 时使用的沙箱环境模板。 
• 状态：当前 Runtime 的运行状态。 
• 关联 Session：使用该 Runtime 的 Session。 
• 创建时间：Runtime 的创建日期。 
• 操作：进入对应 Session 查看详细信息。 
4. Runtime 状态说明 
Runtime 包括以下状态： 
• 运行中：沙箱正在正常提供服务。 
• 休眠：Runtime 因长时间空闲而自动暂停，再次访问 Session 时会自动唤醒。 
• 失败：Runtime 创建或启动过程中出现异常，需要进一步排查。 
页面中的状态可用于判断 Agent 无法执行任务是否与沙箱环境有关。 
5. 查看关联 Session 
点击“关联 Session”列中的 Session 名称，或点击操作列中的 查看 Session，可以进入对应的 
Session 页面，查看会话及运行情况。 
当 Runtime 出现异常时，可以结合 Session 的状态、对话记录和任务执行情况进行排查。 
6. 清理异常 Runtime 
如果某个 Runtime 没有关联的 Session，可能是原 Session 已被删除，但对应的沙箱资源尚未回
收。 
此类 Runtime 建议及时确认并清理，避免持续占用企业运行资源。 
3.4 Session 
“Session”页面用于查看企业智能体产生的会话实例，帮助管理员了解不同用户对 Agent 的使用
情况，并定位对应的 Runtime 运行环境。 

===== PAGE 21 =====
 
1. 查询 Session 
页面顶部支持按照以下条件筛选会话： 
• Session ID：输入会话的唯一标识。 
• 状态：按照活跃、空闲等状态筛选。 
• Runtime ID：查找与指定运行环境关联的 Session。 
• 用户 ID：查询指定用户创建的 Session。 
设置筛选条件后，点击 查询 查看结果；点击 重置 可清空当前筛选条件。 
2. 查看 Session 列表 
列表中展示以下信息： 
• Session ID：系统为会话生成的唯一标识。 
• 名称：会话名称，通常根据会话内容生成，也可能显示为默认名称。 
• Runtime ID：当前 Session 关联的云端运行环境标识。 
• 状态：Session 当前的使用状态。 
• 创建者：创建或使用该 Session 的用户。 
• Agent：该 Session 所属的企业智能体。 
• 创建时间：Session 首次创建的时间。 
• 操作：查看 Session 的详细信息。 


===== PAGE 22 =====
3. Session 状态说明 
Session 可能包括以下状态： 
• 活跃：当前 Session 及其 Runtime 处于可用状态，可继续进行对话和任务执行。 
• 空闲：Session 当前没有持续执行任务，对应 Runtime 可能已进入休眠状态；再次访问时通
常会自动恢复。 
Session 状态主要用于判断当前会话是否仍在使用，不代表历史对话或文件已被删除。 
4. 查看所属 Agent 
点击“Agent”列中的智能体名称，可以进入对应 Agent 的相关页面，查看该会话由哪个企业智
能体创建。 
同一个 Agent 可以被不同用户使用，并分别生成多个独立的 Session。 
5. 查看 Session 详情 
点击操作列中的 查看详情，可以进入 Session 详情页面。 
详情页通常用于进一步查看： 
• Session 的基础信息 
• 关联的 Agent 和 Runtime 
• 当前运行状态 
• 会话及任务执行情况 
• 运行过程中产生的文件或异常信息 
当 Agent 出现任务无法继续、Runtime 启动失败或会话状态异常时，可通过 Session 详情进一
步排查。

3.6 凭据管理 
“凭据管理”页面用于集中保存和管理 Agent 调用外部服务时所需的认证信息，例如 API Key、
访问令牌或账号密钥。 
当 Agent 调用 Connector、MCP 服务、Skill 或外部 API 时，系统可以自动将对应凭据注入请
求，无需在代码或 Agent 配置中明文填写密钥。凭据会加密存储，并仅在运行时解密使用。 
 
 
1. 查看凭据概况 
页面顶部展示企业内凭据的数量及状态，包括： 
• 总计：当前已创建的凭据总数。 
• 活跃：当前可正常使用的凭据数量。 
• 已过期：已超过有效期的凭据数量。 


===== PAGE 28 =====
• 已吊销：已被停用或撤销的凭据数量。 
2. 查询凭据 
可以通过以下条件筛选凭据： 
• 名称：输入凭据名称进行搜索。 
• 状态：筛选活跃、已过期或已吊销的凭据。 
• 服务：按照凭据所对应的服务或 Connector 筛选。 
• 认证方式：按照 Token、API Key 等认证类型筛选。 
3. 查看凭据列表 
凭据列表主要展示以下信息： 
• 名称：创建凭据时设置的名称。 
• Connector 类型：该凭据所属的 Connector 或外部服务类型。 
• 认证方式：服务采用的身份认证方式。 
• 值：凭据内容的脱敏展示。 
• 状态：凭据当前是否可用。 
• 更新时间：凭据最近一次修改的时间。 
• 操作：查看、编辑、吊销或删除凭据，具体选项以页面实际展示为准。 
4. 添加凭据 
点击右上角 添加凭据，在右侧面板中完成配置。添加过程分为“基础信息”和“凭据内容”两步。 
第一步：填写基础信息 
需要配置以下内容： 
• Connector：选择需要使用该凭据的 Connector。 
• 凭据类型：选择对应的凭据或认证类型。可选内容会根据 Connector 自动变化。 
• 凭据名称：填写便于识别的名称，例如“生产 GitHub Token”或“测试环境 API Key”。 
• 描述：补充凭据的用途、所属环境或使用范围，该项为选填。 
填写完成后，点击 下一步。 
第二步：填写凭据内容 
根据所选 Connector 和凭据类型，填写对应的认证信息，例如： 
• API Key 
• Access Token 

===== PAGE 29 =====
• 用户名和密码 
• Client ID 与 Client Secret 
• 其他服务要求的认证字段 
确认信息无误后，提交并保存凭据。 
5. 使用凭据 
凭据创建完成后，可以在 Agent、Skill、Connector 或其他外部服务配置中选择该凭据。 
建议按照不同环境分别创建凭据，例如区分生产环境、测试环境和开发环境，避免多个场景共
用同一组高权限密钥。 
6. 凭据安全建议 
• 不要将密钥直接填写在 System Prompt、代码或普通配置项中。 
• 凭据名称中不要包含完整密钥内容。 
• 对不再使用或疑似泄露的凭据，应及时吊销或删除。 
• 定期检查凭据有效期，并及时更新已过期凭据。 
• 为 Agent 配置满足任务需要的最小权限，避免使用权限过高的账号或令牌。

默认使用 自动分段与清洗。

Embedding 模型 
系统默认使用指定的 Embedding 模型，例如 bge-m3。 
Embedding 模型用于将文档片段和用户问题转换为向量，从而判断不同文本之间的语义相似

默认采用 高质量 索引。

默认采用 向量检索。 
用户查询时，系统会将问题转换为向量，并从知识库中查找语义最相似的文本片段。 
4. 设置检索参数 
Top K 
Top K 表示每次查询最多返回的候选文本片段数量。 
• 数值较小：返回结果更少，内容通常更加集中。 
• 数值较大：返回更多候选内容，但可能包含相关性较低的片段。 
建议设置为 3～5，再根据实际问答效果调整。 
Score threshold 
Score threshold 表示检索结果的最低相关性阈值。 
• 阈值较低：返回的结果更多。 
• 阈值较高：返回结果更少，但通常与问题更相关。 
建议在 0～0.5 范围内调整。若经常检索不到内容，可以适当降低阈值；若召回内容过于宽
泛，可以适当提高阈值。 
完成配置后，点击 确定 创建知识库。 
5. 等待文件处理

处理期间，知识库可能暂时无法正常检索。文件数量较多或压缩包较大时，处理时间可能相应

4.3 Playbook

Playbook 更接近一份可直接套用的实践说明书，并不代表 Agent 创建后即可直接投入生产。用

基本信息

• scripts 
• references

具体目录和文件要求以 Skill SDK 规范为准。 
权限配置 
设置 Skill 的可见范围： 
• 所有成员：企业内所有成员均可查看和使用。

完成配置后，可以选择： 
• 仅保存：保存为草稿，暂不启用。 
• 保存并启用：保存 Skill，并立即允许可见范围内的成员使用。

管理员可以根据企业实际业务设置分类，例如：

创建或编辑 Skill 时，需要从已有分类中进行选择。

Skill 下发策略 
“Skill 下发策略”用于控制指定成员是否可以使用指定 Skill。 
支持以下两类策略： 
• 白名单：仅指定成员可以使用关联的 Skill。 
• 黑名单：禁止指定成员使用关联的 Skill，其他成员仍可正常使用。 
当同一成员同时命中白名单和黑名单时，黑名单优先级高于白名单。 
Skill 下发策略与客户端上传策略相互独立。即使成员拥有上传 Skill 的权限，也可能因为下发
策略无法使用某个指定 Skill。 
创建下发策略 
点击 新建策略，配置以下内容： 
• 策略类型：白名单或黑名单。 
• 策略名称。 
• 作用成员或部门。 
• 关联 Skill。 
列表中可以查看策略类型、作用范围、关联 Skill 和修改时间。点击 权限查询，可以检查指定
成员对某个 Skill 的实际使用权限。 
成员自定义 Skill 
“成员自定义 Skill”用于控制企业成员能否自行上传和管理个人 Skill。 
支持以下四种策略： 
1. 允许所有用户 
所有企业成员均可以上传和管理自定义 Skill。 
2. 白名单模式 
仅白名单中的成员可以上传自定义 Skill，其他成员禁止操作。 
3. 黑名单模式 
黑名单中的成员禁止上传自定义 Skill，其他成员可以正常操作。 
4. 禁止所有用户 
所有企业成员均不能自行上传 Skill，只能使用企业管理员统一配置的内置或自定义 Skill。 

===== PAGE 51 =====
策略修改后会立即生效，并影响所有企业成员。企业对 Skill 安全性、代码来源和外部访问权
限要求较高时，建议采用白名单模式或禁止所有用户。

9.3 远程开发场景下的网络要求 
当企业成员通过 Remote-SSH 等远程开发模式连接远端服务器进行开发时，CodeBuddy 的客户
端运行在本地，但 AI 扩展（genie）部署在远端服务器运行——这是 IDE 远程开发架构的标准
实现：客户端负责界面，扩展代码运行在远端工作区，所有 API 请求均从远端服务器发出。 
若远端服务器未配置内网 DNS，请求将从公网出口发出；如该出口 IP 不在企业 IP 白名单内，
请求将被服务端拦截（返回 403 / IP Access Restricted） ，导致 AI 功能无法使用。 
 
配置建议 
为确保远程开发场景下 AI 功能正常，管理员可按以下方式配置： 
1. 配置内网 DNS（推荐）：在远端服务器上配置内网 DNS 解析，或将企业 endpoint 通过 
hosts 文件指向内网 IP，使请求从内网通道发出，自动命中内网段白名单。 
2. 添加公网 IP 白名单：前往「企业设置 > 网络设置 > IP 白名单」 ，将远端服务器的公网出口 
IP 加入白名单。建议按出口 IP 段添加（如 /24） ，避免因 IP 变化导致再次拦截。 
 
IP 白名单行为说明 


===== PAGE 74 =====
CodeBuddy 设置 IP 白名单后严格执行 IP 限制。若访问来源 IP 不在白名单内，客户端将被立
即登出，无法登录管理后台和客户端，以最大限度保证企业资产安全。 
排查提示：若成员反馈「IP Access Restricted」错误，可要求成员提供 renderer.log 中的 
remoteAuthority 字段。若取值格式为 codebuddy-remote-ssh+<IP>（如 codebuddy-
remote-ssh+10.130.30.24） ，说明请求来自 Remote-SSH 远端服务器，请按上述方式配
置网络。

14. 常见问题 
Q1：成员无法登录旗舰版，提示没有授权？ 
请前往「成员授权 > 成员与部门」检查该成员是否已被授权客户端。如未授权，勾选该成员
并点击「授权客户端」 。 
Q2：席位已满，如何添加更多成员？ 
前往「订阅与用量 > 订阅管理」 ，点击「扩容席位」购买更多席位，或取消不活跃成员的授权
以释放席位。 
Q3：月度用量不够用怎么办？ 
有两种方式：1) 在「订阅管理」页面点击「购买加量包」购买额外用量；2) 在「成员用量」
页面调整高消耗成员的周期限量。 
Q4：如何接入企业私有模型？ 
前往「AI 资源管理 > 模型设置」 ，点击「新增自定义模型」 ，填写模型名称、模型 ID 及 API 部
署地址（需兼容 OpenAI 协议） ，保存后启用即可。 
Q5：如何查看谁在使用管理后台？ 

===== PAGE 82 =====
前往「日志管理 > 操作日志」 ，可查看所有管理后台的登录和操作记录，包含操作人、IP 地址
和操作时间。 
Q6：如何配置团队统一的 AI 行为规范？ 
前往「AI 资源管理 > 自定义指令」 ，通过全局提示词和自定义指令来统一团队的 AI 使用规
范。
